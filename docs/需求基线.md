# 校园火险多源感知预警系统需求基线

版本：1.0，2026-09-26

## 1 目标和边界

系统面向单个固定摄像机监测单个校园配电设施周边区域。视觉检测固定为烟雾、明火、落叶堆积三类。配电设施位置由人工配置 ROI 多边形表示，第一版不增加配电箱检测类别。

系统融合视觉、温湿度、烟雾、火焰和红外测温信息，输出正常、关注、预警、报警四级状态。电气异常只允许使用非接触测量、低压模拟或外部数据输入，不直接接触高压设备。

## 2 第一版功能需求

1. 接收图片、视频或帧目录，输出检测框、类别、置信度、帧号和时间戳。
2. 判断落叶、烟雾和明火检测框与配置 ROI 的空间关系。
3. 接收带时间戳和有效位的传感器数据，拒绝把缺失或过期数据当成正常值。
4. 根据持续时间、恢复条件和多源证据更新四级风险状态。
5. 保存触发原因、解除原因、检测摘要、传感读数、模型版本和规则版本。
6. 建立浮点模型、整数参考、RTL 仿真和板级运行之间可追溯的验证链。

## 3 非功能需求

- 可复现：数据划分、训练配置、模型、日志和实验结果必须能互相追溯。
- 可解释：每次风险状态变化必须能定位到具体视觉或传感证据。
- 失效可见：相机停帧、传感器失联、推理超时和模型不匹配必须显式报告。
- 资源受控：硬件采购预算上限为 1000 元，现有电脑不计入该预算。
- 安全边界：不进行真实高压漏电或故障电弧实验。

## 4 模型与 FPGA 第一版约束

模型首选输入为 128×128，96×96作为对比。第一版算子集合优先限制为 3×3/1×1 卷积、步长 1/2、ReLU、重量化以及确有需要的简单池化。复杂注意力和不易定点实现的激活暂不进入第一版。

初始量化目标为 W8A8、对称量化、零点 0、int32 累加。该规格是待实验验证的设计目标，不是已经完成的实现结论。

## 5 完成定义

“软件基线完成”要求固定数据和配置可重复运行；“整数参考完成”要求 Python 与独立 C 实现逐位一致；“RTL 完成”要求与整数参考逐位对拍通过；“部署完成”要求真实板卡运行并保存资源、时序、输出和耗时证据。四种状态不得互相替代。

## 6 当前已知未决项

- FPGA 板卡、摄像头和传感器尚未采购。
- 校园场景数据尚未采集。
- 传感器阈值、持续时间和恢复阈值尚未标定。
- 最终模型结构、实际精度和板级性能尚未验证。
- 学校可借用设备和算力尚未确认。
