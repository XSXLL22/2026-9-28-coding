## 2. 技术路线(本项目已固化的方法论)

1. **溯源纪律**:冻结种子(训练 seed 显式给出且禁止复用冻结种子 20260926)、权重/数据/脚本 SHA256 入档、失败目录保留不覆盖、重跑必须用新目录并用确定性(同种子首轮逐值一致)证明重跑有效。
2. **先声明后执行**:每个实验先写"训练前计划"(方案网格、验收门槛、限制),跑完只补执行记录;决策门(P4.7 的 -3pp)在看到结果前声明。
3. **合同先行**:定点行为写成版本化合同(机器可读 JSON + 人读文档),Python/C/未来 RTL 都只对着合同实现;**任何修订升版本并重生成下游产物**。
4. **单一事实源**:P4PKB1 二进制模型包(层描述符 + int8 权重 + 乘子/移位 + SiLU 查表)是 Python 参考、C 参考、将来 RTL 的共同输入;两参考不共享代码,只共享包格式与合同。
5. **逐位对拍**:bit-exact 只要求于合同覆盖域(Python↔C↔RTL);float↔int 之间是量化误差,用统一口径的 AP 评估 delta。
6. **验证器即验收**:`tools.verify_golden_vectors` 三方对拍(冻结期望 ↔ Python 重算 ↔ C 重算,逐节点 sha256),任一不一致退出码非零。

## 4. 踩坑记录(根因 → 修复 → 教训)

### 本会话自己的错误

1. **子进程命令多带 `python` 前缀**:`run()` 已自动加 `sys.executable`,内联调用又写了 `['python', '-m', ...]` → 两臂训练 30 分钟完成后在评估阶段崩(exit 2)。修复后按惯例保留失败目录、retry1 完整重跑,报告器核对重跑与失败运行首轮逐值一致(确定性)。**教训:命令拼装统一走一个出口;长流程先空跑参数检查。**
2. **报告器精确字符串比较**:`report['training_audit_check'] != 'passed'` 而实际值是 `'passed: arms and frozen baseline identical'` → 误判失败。改用 startswith。教训:状态字段要么存布尔,要么匹配前缀。
3. **FP 配对账目不闭合**(12+17≠30):多对一匹配所致,补 `matched_old` 计数。教训:配对统计必须给守恒式。
4. **直方图喂带符号值**:cls 头末层输出全负,落在 [0,max] 范围外 → 直方图全零 → p999=NaN → JSON 序列化崩。修复:统计 |值|。教训:量纲统一的统计前先想清楚符号域。
5. **校准最初只收集卷积输出**:合同要求 concat 输出 scale 也是校准产物,而 C2f/SPPF 内部 concat 无模块钩子 → 扩展为从执行器收集 conv+concat。教训:scale 挂在"张量"上,"张量的生产者"才是收集单位。
6. **C 端三类索引/解码 bug(全部被 golden 验证器捕获)**:①int32 位模式 memcpy 进 int64 数组未做 4→8 转换,读到越界垃圾;②conv/maxpool/upsample 读索引通道步长少乘 w;③maxpool/upsample **写**索引通道步长少乘 w_out → 128 通道互相覆盖,出现 `[63,5,69,24]` 的怪输出。教训:位宽转换绝不用 memcpy;CHW 三维索引写成统一 helper;调试时先确认"输入视图正确"再怀疑算法。
7. **反复用 heredoc 打补丁破坏 C 字符串**(`\n` 被转成真实换行),且一次 `2>/dev/null` 吞掉编译错误 → 陈旧 exe 产生自相矛盾的调试输出,浪费多轮。教训:改 C 用 Edit 工具;编译器输出永不被吞;调试前先确认 exe 与源码同步。
8. **杂项**:环境变量合并 `dict(**os.environ, PYTHONUTF8='1')` 在 PYTHONUTF8 已存在时 TypeError(改 `{**os.environ,...}`);fusion 快照字段名记错(`reason_codes` 不是 `health_reasons`);transitions 从快照取(快照无 previous_risk_level,只有 events 有);verify 工具路径拼接把主包拼进向量目录、numpy 导入丢失、sed 式补丁弄坏缩进;working-point helper 用字符串 cls 过滤整数类别(TP=0);负样本计数用了 0.001 候选阈值而非 0.25 工作点。

### 合同/设计层发现(通过修订链固化)

9. **合同 1.0 三处错误**(P4.1 审计发现,产物生成前):BN 折叠偏置漏减均值(`b_fold = β + (b0−μ)·γ/√(var+eps)`);整数边界写错(Ultralytics 的 DFL 是 softmax **之后**做固定卷积 → DFL/softmax/解码全属 PS_FLOAT,整数终点 = 检测头 6 个原始分支输出);漏了残差 add 算子与 concat 输入重量化规则。
10. **合同 1.2 修订**(浮点对拍发现):maxpool 边界必须是 -inf 语义(补零会污染全负窗口;int8 下用 -128 填充即精确等价)。
11. **框架行为差异**:Ultralytics `y` 列表索引 y[i+1]=层 i 输出、y[0]=网络输入;Detect 的 f 是列表需在层循环特判;`decode_bboxes` 默认输出 **xywh**(自研解码器输出 xyxy,验证时必须转换——分数差 2e-7 证明其余全对)。
12. **maxpool 填充语义**:框架 `MaxPool2d(padding=2)` 是 -inf;自写"先 pad 0 再池化"在全负窗口会取到 0——浮点对拍最大偏差 0.134 集中于此,由此触发合同 1.2。
