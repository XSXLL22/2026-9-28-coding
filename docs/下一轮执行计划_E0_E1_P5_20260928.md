## 1. 目标、顺序与完成边界

下一轮目标：让量化精度结论可信，并建立一个可逐位验证的 FPGA 卷积原型。顺序如下：

`E0：修复评估 → E1：定点合同/来源/资源复核 → P5.0：单算子 RTL 仿真 → 交接`

每段通过后继续下一段，不要只提交计划或脚手架。若某段失败，保留失败证据，修复根因后再验收；依赖未满足时不能宣布下一段通过。E0 受阻时可整理 E1/P5 接口，但不能用旧量化损失驱动 QAT。E1 数值语义未确定时，不能冻结 RTL 数值实现。

本轮完成边界是 **P5.0 的最小 3×3 卷积逐位仿真**。P5.1 的行缓存优化、更多卷积形态、AXI 配置、综合和整网调度是后续任务。QAT、W8A16、学生模型属于后续路线决策，本轮只根据修复后的证据给出建议，不顺带开展训练。

保留约束：现实采集、采购和上板暂缓；预算仍为 1000 元；16 张 test 不参与推理、调参或校准；不修改共同开发集标签；软件默认仍为原 FP32 128，320 保留为研究候选；P3 默认规则不变。

## 3. E0：修复并复验量化评估

### E0.1 先把已确认错误变成回归用例

现状：`letterbox_128_rgb` 将原图等比例缩放后补边，`load_gt` 将横纵归一化坐标直接乘 128。开发集全部 109 张图非正方形，GT 与预测框不在同一坐标空间。

先保存可复现的失败测试/诊断输出，再修复。真实回归样本可用 `WEB06156.jpg`（768×432 → 128×72，上下各补 28），并增加不依赖公开图片的合成几何用例。测试应检验正确行为，不能把错误旧输出固化为“期望”。

**最低用例矩阵：**

| 场景 | 必须验证的性质 |
|---|---|
| 横向、纵向、正方形图 | GT 与图片使用同一变换；完美预测可匹配 |
| 奇数补边、缩放尺寸取整 | 左/右、上/下补边不等时仍可逆；与采用的框架规则一致 |
| 靠边框、跨出画布预测 | 裁剪发生在哪个坐标域有明确约定，无负面积框 |
| 空标注、无预测 | 不崩溃；FP/FN/负样本计数正确 |
| 重复预测、类别错误、多目标竞争 | 一对一匹配及类别规则符合选定评估实现 |
| 几何往返 | 原图框 → 画布 → 原图误差在预先声明容差内 |
| 错配包/权重/校准文件 | 运行昂贵推理前拒绝，返回非零退出码 |

### E0.2 建立唯一的坐标变换实现

推荐以**原图像素坐标**作为最终匹配空间：原始 YOLO 标签乘原图宽高得到 GT；网络框根据预处理记录的 gain 和 padding 逆变换回原图，然后裁剪、匹配。

预处理必须返回图像及变换元数据：原尺寸、输入尺寸、缩放后的实际尺寸、gain、四侧 padding、通道顺序、归一化方式。正向与反向复用同一记录，不能分别猜测 padding。

采用当前框架的 letterbox 几何约定，并核对浮点 gain 与缩放尺寸取整的关系；不能在正向使用框架 gain，反向又改用另一套按取整尺寸推导的比例。使用哪个约定应写入报告，并用同一输入与框架对齐。

可抽取小型公共预处理/几何模块，但避免顺便重构全部训练和运行入口。现有默认运行行为无关的部分应保持不动。

### E0.3 补齐评估输入的来源与兼容性检查

最小修改方案：为评估入口增加显式校准报告参数，核对其哈希与模型包声明一致；不得继续静默读取固定实验目录的 scale。当前包不包含完整输出反量化 scale 时，不要凭 tensor ID 相同就认定来自同一模型。

推理前必须核对：

- `.pt` 权重哈希 = 包内权重哈希 = 校准报告权重哈希。
- 实际包哈希 = 外部模型包清单声明；实际校准报告哈希 = 包内声明。
- 合同版本、输入形状、类别顺序、图结构及六个检测头输出的身份/shape 相容。
- 输出 scale 明确绑定输出节点/张量；数量、有限性、正值检查通过，不能靠字典遍历顺序凑六个 scale。
- 109 张开发图及标签与冻结审核清单一致；64 张校准样本来自训练集，评估阶段不重选样本、不更新 scale。

E0 先使用原整数包和原校准参数验证评估修复，**不要同时重新校准**，否则无法区分评估修复与量化策略变化。若来源不符或包损坏，先定位并记录，不用新产物冒充旧包。

### E0.4 逐层建立 FP32 一致性，不只比较最终 AP

三条路径使用相同模型身份与图像清单：

- F0：原框架浮点网络。
- F1：现有折叠浮点执行器。
- Q0：当前冻结整数包。

先比较 F0/F1，再比较 F1/Q0。F0 与 F1 尽量复用同一输入 tensor、同一后处理和同一评估器，以隔离导出问题。另用框架原生验证路径核对端到端设置；不得要求不同设置产生相同数字。

| 检查层次 | 验收方式 |
|---|---|
| 输入 | 相同字节/浮点数组、RGB 顺序、归一化、尺寸、补边 |
| 原始 head 输出 | 六输出逐一比较；保存最大绝对误差及发生位置 |
| DFL/解码 | 相同框格式与 stride；明确 xywh/xyxy，框误差与分数误差分开 |
| NMS | 同置信度、IoU、类别处理、multi-label、max_det、排序/并列规则 |
| 坐标还原与匹配 | 同原图坐标、裁剪、类别、一对一匹配和 IoU 阈值 |
| AP | 同一可信实现与插值规则；保存每类和汇总结果 |

建议预声明的数值诊断容差：沿用既有折叠节点绝对误差 `1e-4`；解码画布坐标误差 `1e-3` 像素、分数误差 `1e-5`；几何合成往返误差 `1e-4` 像素。这些是验证目标，不是可在失败后随手调大的参数。触及置信度/NMS/匹配边界导致离散差异时，输出具体样本、分数、IoU 和双路框，解释是否为数值边界效应。

完整同设置 FP32 对照以 mAP50 差异不超过 **0.1 个百分点**作为诊断门槛，并检查 TP/FP/FN 是否一致。超过门槛不能写“评估实现不同所以不可比”后直接放行；先逐级定位。确需修订容差时，保存旧失败结果、依据与新规则，不能为了触发或绕过 QAT 门而放宽。

AP 优先复用已锁定版本的框架指标实现。若保留自研 AP，必须用固定预测在两种评估器间验证插值、匹配与类别平均差异，写清它是辅助指标；QAT 门使用一个预先固定的主指标。

**两个独立设置：**主 AP 使用 conf=0.001、NMS IoU=0.7，其他参数明确与参考验证对齐；固定工作点使用 conf=0.25、NMS IoU=0.45、匹配 IoU=0.5。不得把 P4 旧工作点的 NMS=0.7 混作 R1 的 0.45。改变 NMS 必须从 NMS 前候选重做，不能筛选已有 NMS 输出冒充。

## 4. E1：定点合同、独立参考及资源估算复核

### E1.1 数值域与实际拒绝行为

需要检查和修正的具体位置：`training/pack.py` 的 `accumulation_bound`、包构建调用点、`tools/build_p4_resource_report.py` 的界估算、Python/C 重量化实现。

- 激活存储允许 [-128,127]，不能无条件使用最大绝对值 127；权重的最大绝对值必须先展宽再取绝对值，避免 int8 的 `abs(-128)` 溢出。
- 建议按输出通道用 `B[o] = abs(bias[o]) + max_abs_input * sum(abs(weight[o]))` 建立保守界；也可保留更松的乘积界，但需证明覆盖完整合法输入域。尾通道填充取零时不能凭空计为非零数据。
- 查实超界是否真的抛错。当前函数调用旁“raises”注释不能替代实际检查；在转成 int32、写包之前必须拒绝非法偏置/累加界。
- 同时检查重量化乘积与舍入常数的中间位宽，而不只检查 int32 累加。用 Python 任意精度整数作边界判据，避免检测代码自身先溢出。
- 明确 shift=0、shift 上限、M 归一化边界、正负半值舍入。不能让 Python 的负移位/数组溢出、C 的未定义有符号溢出或 RTL 的表达式截断成为隐含实现。
- 若某些合法参数当前不能支持，应在合同/入口显式拒绝；不能让测试避开它们，同时文档仍声称支持。

测试至少覆盖：全负权重且最大绝对值不等于正向最大值、输入 -128、偏置边界、恰好可接受与超界输入、正负半值、shift=0、非法移位、M 临界值、饱和两端。用手算的小例子或独立高精度判据验证，不让待测函数自己生成全部期望。

### E1.3 重写资源结论

按不同器件单列 7010 的 80 DSP、7020 的 220 DSP，引用已有 [AMD 官方资料](https://www.amd.com/content/dam/xilinx/support/documents/selection-guides/zynq-7000-product-selection-guide.pdf)，核对片上 RAM 等参数时也使用官方资料。

报告至少区分：

## 5. P5.0：无硬件的最小 RTL 闭环

### P5.0a 冻结单算子接口与向量格式

先写接口说明再编码。目标是有符号 int8 卷积，偏置/累加位宽遵循 E1，逐通道 M/shift 重量化后饱和输出 int8。**最小算子输出默认取 SiLU 前值**；SiLU 仍留在 PS_INT，不顺手改成 ReLU。

建议拆为：MAC/累加、重量化与饱和、简单卷积控制、测试台；具体文件名由执行者确定，放入 `hardware/rtl/`、`hardware/tb/`。使用可综合结构；纯测试设施留在测试台。

接口必须写清：时钟/复位、任务开始与完成、错误状态、配置锁存时刻、张量布局 CHW、卷积权重 OIHW、输入/输出遍历顺序、padding 零值、偏置加入次数、每通道乘子与移位、valid/ready 接收条件。运行期间配置不支持修改时，应明确拒绝或禁止，不能出现半任务切换。

先采用单 MAC 或小并行度实现，允许仿真用存储器加载整块小张量；不把该结构宣称为流式行缓存或高性能整网加速器。首版支持 3×3、stride=1、明确选定的 padding 与尺寸上限；未支持配置必须可检测，不能静默按其他配置执行。

单算子向量包含：版本、层名、包哈希、输入/输出 shape、布局、padding/stride、输入 int8、权重 int8、偏置、M/shift、可选累加期望、SiLU 前 int8 期望、各文件哈希及随机种子。

现有 `conv2d_int8` 内部已经做了 SiLU，所以不能直接将其最终输出当成 PL 模块期望。通过可审计的中间输出导出或独立小参考得到边界期望；确保不改变既有整网输出。向量生成不得依赖 RTL 实测结果。

### P5.0b 按三个可独立验收的小步实现

| 小步 | 实现 | 通过后保存 |
|---|---|---|
| A | 有符号乘加及偏置 | 手算/高精度边界对拍，累加溢出约束证据 |
| B | M/shift、舍入、饱和 | 正负半值、shift=0、饱和两端的逐位结果 |
| C | 小尺寸 3×3 卷积控制 + A/B | 每个输出元素与 Python/C 对照，连续任务及反压测试 |

首轮建议使用尺寸小而有辨识力的合成张量：空间 3×3、5×7；Cin 包括 1、3、5，Cout 包括 1、2、3；覆盖多输入、多输出通道及非整齐尾通道。若硬件设计声明通道并行度，再加入该并行度的 `P-1/P/P+1`。不是要求盲目穷举所有组合，选取能覆盖各风险的组合并记录覆盖表。

再抽取实际包中受首版支持的至少一个 3×3 stride=1 层做真实中间张量验证。资源过大时可增加独立小张量测试，但不能把它标为完整真实层通过；应扩展仿真容量或如实保留真实层未验收状态。

### P5.0c 必须验证的时序行为

- `valid && ready` 才接收；输出被反压时，valid/data 保持稳定直到接收。
- 随机输入停顿、随机输出反压，不丢失、不重复、不乱序；期望结果与无停顿运行完全一致。
- 上电复位、任务中复位、连续两任务不同配置；复位后没有旧结果泄漏，重新提交任务可以完成。
- 使用非对称输入/权重识别通道步长、行列索引错误，避免全零/全一向量掩盖布局 bug。
- 成功输出数量严格等于 Cout×Hout×Wout；定义超时上限，死锁或输出数量错误必须失败。
- 未支持 kernel/stride/尺寸/通道/移位的配置有明确行为与测试，不能输出看似合理的静默结果。

使用 Icarus Verilog 11.0（开工时再确认路径），编译和仿真分别保存退出码与日志。比较脚本发现任一数据/数量/协议差异必须非零退出；不能靠搜索控制台的“PASS”作为唯一验收。

**P5.0 交付：**RTL、接口说明、向量格式、生成器、测试台/驱动、确定性随机种子、逐位结果、时序/协议检查、至少一个可打开波形、完整复现命令及阶段简报。记录周期数与仿真时间，不宣称已综合、达到某 MHz 或获得板上 FPS。

## 6. 报告、失败与中断恢复规则

所有新实验使用机器可读状态，建议将 `status` 与解释文字分开：`running/complete/failed/blocked` 加 `reason`，不要依赖“passed: 一段描述”的字符串前缀判断。

报告通用字段：节点 ID、开始/结束时间与时区、命令及退出码、数据/权重/包/校准/合同/源码哈希、环境、参数、产物路径、检查结果、失败明细、限制和下一步。测试数量以实际输出为准，不能把旧 94 与新增数量手算后当作运行结果。

失败保存完整日志，修复后使用新结果目录。评估后处理失败但网络原始输出缓存完整时，可以从经哈希验证的缓存继续后处理；不用为了“流程完整”再重训或重复几十分钟网络计算。必须记录恢复点，不能伪装首次成功。

中断时写清：已通过哪些检查、还在运行的进程/任务、最后完成样本或向量、源码修改、下一条应执行的命令、不能复用的产物。不要将“文件已生成”写为阶段完成。

每节点结束更新 `experiments/阶段简报.md`、当前交接入口和 README 的最新状态。历史报告原始数字保留，顶部添加更正链接即可；不要让多个文档同时把互相矛盾的结论标为“最新”。

建议新文档：`experiments/P4评估修复简报.md`、`experiments/P4合同与资源复核简报.md`、`experiments/P5最小卷积仿真简报.md`、`docs/E0_E1_P5完成后交接.md`。这些是计划中的产物，当前尚不存在或尚未完成，执行者应先检查是否重名。
