## 已处理的工程问题

训练、评估和推理现已支持软件诊断尺寸 320。复核使用 `--size-reference 128` 保持目标分组不变；比较必须显式使用 `--allow-cross-size`，同时检查 NMS、目标几何、分组参考和逐目标分组。

第一次训练仅完成第 1 轮计算，在 Polars 保存阶段报 `unknown feature flag: sse3`。根因是启动环境缺少 Windows 处理器架构字段，现由 `runtime.common.restore_windows_architecture` 从系统接口恢复缺失信息，保留实际 CPU 检查。没有更换依赖或跳过检查。原失败目录 `p2_r1_resolution320` 保留；成功结果位于 `p2_r1_resolution320_retry1`，二者首轮已保存数值完全相同（排除耗时）。训练前新增真实 CSV 读取检查。

不要继续使用失败目录中的第 1 轮记录作为已完成实验，也不要覆盖任何历史实验目录。

## 后续节点，按顺序推进

1. **R1.1 收益重复验证**：选择一个新的固定种子，同时跑 128 与 320 两个配套实验，其余使用原配方和相同数据；不要只重跑 320 与旧种子 128 比较。保存新目录、权重和逐图结果。报告两次配对结果，只有两个种子仍不能宣称充分的统计稳定性。
2. **R1.2 新增误检分类**：先复核 R1 相比原模型多出的 FP，区分无目标背景误认、目标局部/范围失配、重复框、跨类别问题与待核标注。重点样本 `WEB04713`、`WEB06156`，分类写入单独人工台账；本轮只看过三张代表图，不能扩充为全量原因统计。
3. **R1.3 工作点比较**：基于冻结候选，在开发集上预先约定少量每类阈值/NMS 方案，同时报告召回、框 FP、负样本图片误检；若改变 NMS，必须重新推理，不可仅过滤现有预测冒充 NMS 对照。测试集继续保留。
4. **P3 对接验证**：确认候选与工作点后，使用实际 320 检测日志重做离线适配与模拟融合回放，检查模型来源、时间戳和风险变化。仅算软件兼容性，不能据公开静态图片宣称校园报警验收。

本轮未启动上述节点。ROI/切片、蒸馏、量化等继续排在收益确认和误检诊断之后。当前小目标仍漏检 70/93，实际采集暂缓；采购、开发板选型和 P3 默认规则没有变化。

## 复现入口

`python -m tools.run_r1_experiment --output experiments/新的唯一目录` 会从官方 YOLOv8n 初始化开始完整 50 轮 R1 实验，固定 seed=20260926；它不是多种子工具。开展 R1.1 时应增加显式种子配置及配套参考约束，不能静默修改已冻结脚本。

`tools.report_r1_experiment` 是本次重跑的专用报告器，含首轮失败/重跑对照检查，不应当作通用多种子报告器。人工解读另补在本轮简报。
