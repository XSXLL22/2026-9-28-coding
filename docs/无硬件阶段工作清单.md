# 无硬件阶段工作清单

当前工程只有任务书、开题报告和架构文档，还没有模型代码、参考推理代码、RTL 或板级工程。因此现在的重点不是等待采购，而是把软件链路和验证标准做成，硬件到手后直接接入。

## 现在可以完成的工作

### 1. 固定需求和数据规范

- 固定三类标签：`smoke`、`fire`、`leaf_pile`。
- 编写正样本、困难负样本和无效样本的标注规则。
- 定义配电设施 ROI、目标框与 ROI 的相交规则、连续帧确认规则。
- 规定训练集、验证集、测试集按地点和视频分组，避免相邻视频帧泄漏。
- 建立一份样例数据和标注质量检查脚本，即使初期只有少量自采图像也可以运行。

验收结果：任意一张图片都能按规则判断是否应标注、类别是什么、是否属于测试集。

### 2. 完成电脑端软件基线

- 支持图片、视频和离线帧序列输入。
- 输出三类目标框、类别、置信度和时间戳。
- 保存统一格式的检测 JSON，供后续融合和硬件回放使用。
- 用固定 ROI 判断落叶是否位于配电设施周边。

验收结果：不接摄像头也能对同一批输入重复运行，并生成相同的检测结果和日志。

### 3. 完成多源融合的离线回放

硬件传感器尚未采购时，用 CSV 或 JSON 模拟温度、烟雾、火焰、红外测温数据。先实现：

- 数据时间戳、有效期和传感器失联状态；
- 正常、关注、预警、报警四级状态；
- 升级阈值、降级阈值和持续时间；
- 触发原因、解除原因和事件记录；
- 摄像头停帧、传感器失联、时间错位、推理超时等故障场景。

验收结果：给定一组固定回放数据，系统能解释每次状态变化，并且重复运行结果一致。

### 4. 训练和量化小模型

- 先用轻量 YOLO 建立浮点软件基线，不追求直接达到最终模型规模。
- 比较 128×128 和 96×96 输入。
- 优先使用普通 3×3/1×1 卷积、步长卷积、ReLU 和简单检测头。
- 先做 PTQ，分析每层量化误差，再做 QAT。
- 导出每层尺寸、权重、偏置、量化尺度、MAC 数和内存需求。

验收结果：得到一个只包含约定算子的模型，并能导出为逐层整数参数；模型是否达到最终精度要以测试集数据为准。

### 5. 建立 Python/C 整数参考模型

这是没有硬件时最值得提前完成的部分。参考模型要明确实现：

- int8 权重和激活格式；
- BN 折叠；
- int32 累加；
- 乘法器和移位参数；
- 负数舍入；
- ReLU、饱和和 padding；
- 输入输出张量布局。

每一层保存 golden 输入和输出，后续 RTL 只需对比这些文件。不要等 FPGA 到货后才确定定点规则。

验收结果：Python 与 C 对同一层、同一组随机输入逐位一致；边界输入也能通过。

### 6. 先做 RTL 算子和仿真

不需要开发板即可完成：

- 3×3 卷积；
- 1×1 卷积；
- ReLU 和重量化；
- 小型 MAC 阵列；
- 行缓存或窗口生成；
- AXI-Stream 风格 valid/ready；
- AXI-Lite 配置寄存器模型；
- RTL 与整数参考逐位对拍。

综合可以先使用目标器件的候选型号，得到资源和时序趋势。板卡型号未确定时，综合报告只能作为估算，不能写成最终硬件结果。

## 现在不能声称已经完成的内容

- 真实摄像头采集和实际传感器标定；
- FPGA 上的真实帧率、功耗、资源占用和时序收敛；
- 独立运行的板端系统；
- 真实环境下的误报率、漏报率和报警延迟；
- Zynq、Kintex 或其他具体芯片上的最终部署能力。

电脑上的视频回放、RTL 仿真和综合结果可以作为阶段证据，但必须标明“离线”或“仿真”，不能替代上板测试。

## 推荐推进顺序

1. 先建立数据格式、检测 JSON 和传感器回放格式。
2. 实现电脑端检测基线和四级风险融合。
3. 固定模型算子集合，完成 PTQ 与模型规模估算。
4. 完成 Python/C 整数参考和 golden vectors。
5. 实现单个卷积算子 RTL，对拍通过后再扩展到多层。
6. 根据综合资源结果反推候选板卡，再决定采购。
7. 硬件到手后先做 JTAG、DDR、GPIO 和单层 DMA 验证，再接入整网。

## 当前阶段的最终产物

在硬件采购前，至少应形成：数据与标注规范、软件检测基线、传感器模拟回放、风险融合模块、量化模型、整数参考、golden vectors、至少一个通过仿真的 RTL 算子，以及一份候选板卡资源需求表。
