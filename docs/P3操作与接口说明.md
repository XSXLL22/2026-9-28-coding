# P3 离线融合操作与接口说明

更新：2026-09-27。当前规则版本 `simulation-fusion-1`，仅用于模拟回放。实现见 [runtime/fusion.py](../runtime/fusion.py)，结果见 [P3 简报](../experiments/P3离线融合简报.md)。

## 当前支持范围

单节点、单会话、共同毫秒时钟；两条流固定为 `vision` 与 `ambient_temperature`。视觉须声明支持 smoke=0、fire=1。可以携带 leaf_pile=2，但当前没有落叶规则；空烟火检测不能说明不存在落叶。

融合不接设备、不控制蜂鸣器、不自动执行采购或网络服务。输入 `origin=simulation`，配置 `simulation_only=true`；目前拒绝真实测量来源，防止把示例阈值误当生产规则。

## 一次可运行的演示

以下命令在项目根目录执行；输出目录需要是新的。

```powershell
.\.venv\Scripts\python.exe -m tools.run_p3_demo --output experiments/p3_demo_next
```

产生 8 个场景的 `input.jsonl`、`ticks.json`、`snapshots.jsonl`、`events.jsonl` 与报告；每个场景自动重复回放检查一致性。

对已有记录独立回放：

```powershell
.\.venv\Scripts\python.exe -m runtime.fusion --input experiments/p3_simulation_release1/fresh_recovery/input.jsonl --ticks experiments/p3_simulation_release1/fresh_recovery/ticks.json --config configs/fusion_simulation.json --output experiments/p3_recovery_next
```

现成结果都在 [最终模拟报告](../experiments/p3_simulation_release1/report.json)，不必为了查看结果重新运行。

## 输入合同

共有字段：`schema_version=1`、`node_id`、`session_id`、`clock_id`、`record_id`、`origin`、`stream_id`、`kind`、`sample_time_ms`、`available_time_ms`、`valid`、`invalid_reason`、`health`。

- 时间为非负整数毫秒，available 不早于 sample。会话不接受未映射的时钟。时间清单的 tick 严格递增，即使没有新记录也要提供 tick 以发现断流。
- valid 为布尔值；有效输入要求 health=OK 且 invalid_reason=null，无效输入需提供原因。JSON 的 NaN、Infinity、布尔冒充数值等均不能成为有效证据。
- 相同 record_id 且内容完全相同可去重；同 ID 不同内容报错。较旧/相同采样时间不覆盖新记录。有效视觉的 frame_id 也必须推进，重发帧不能推进持续时间；较新时刻的明确无效/故障记录允许沿用帧号，避免掩盖相机故障。

环境温度额外字段：`sensor_id`、`sensor_type=ambient_temperature`、`value`、`unit=degC`、`calibration_status=simulation_only`。无效读数必须为 null，不能用 0 代替；当前没有把绝对温度解释为“温升速率”。

视觉额外字段：`frame_id`、`model_sha256`、`run_sha256`、`vision_config_sha256`、`supported_classes`、`roi_status`、`image_width`、`image_height`、`confidence_floor`、`detections`。每个检测包括项目类别、置信度、原图像素框及 `roi_box_area_fraction`。框必须在原图范围内且非空；未知类别、未支持类别及低于声明过滤阈值的框均拒绝。

所有模型身份哈希是来源标识，不是精度认证。模拟场景使用明确由字符串生成的合成身份，真实 P2 适配保留实际模型哈希和原运行来源。

## 时间、风险与健康语义

1. 回放先校验所有输入，再按 available、sample、record_id 稳定排序。同一 available 时刻成组更新，避免同一组中的先后顺序影响组合判断。较早的完整模态样本可被同组更新样本替代，不用一次迟到批次伪造持续观察。
2. 仅消费 available≤tick 的记录。数据年龄由当前时刻减 sample 算出；不是读取输入自报的年龄。
3. 持续区间由新的采样时刻推进。组合规则使用两条支持流中较早的采样时刻，且要求两者时差在 alignment_ms 内。相同证据不能靠等待 tick 满足持续时间。
4. max_gap_ms 限制区间连接，并保守地约束“融合可用时刻距上次支持采样”的间隔；迟到数据不能跨过本应中断的观察区间。该限制与 max_age_ms 分开，慢推理可能打断持续性，需要未来按实际链路时延重新标定，不能为通过演示随意放宽。
5. 只允许立即升级到已满足的最高等级；较弱证据不会自动降级。首版降级采用共同恢复门槛，满足后直接 NORMAL，尚无逐级恢复策略。
6. 已知风险在断流或证据不足时保留，并保存建立风险的原始依据。NORMAL 在过期后也只是最后已知状态，`risk_assessment_valid=false`，不能在界面上显示成“当前安全”。

健康 OK 表示所需输入新鲜有效、时间对应且视觉过滤阈值足以检查恢复；部分受限为 DEGRADED，两流均不可用为 UNAVAILABLE。风险初始为 null，即使健康 OK，也要足够持续观察后才有风险结论。

评估有效性表示本原型所需输入覆盖及已有结论是否齐备，不证明现场安全。强视觉单源可以 ALARM，同时 health=DEGRADED、risk_assessment_valid=false；使用方不能因为评估受限就丢弃已知报警。

## 模拟规则

完整数字集中在 [fusion_simulation.json](../configs/fusion_simulation.json)。所有数字均未经过现场标定。

| 规则 | 条件与默认持续时间 | 输出 |
|---|---|---|
| weak_visual | 烟或火分数≥0.25，持续 500 ms | ATTENTION |
| warm_ambient | 模拟环境温度≥45°C，持续 500 ms | ATTENTION |
| persistent_smoke | 烟雾分数≥0.6，持续 1500 ms | WARNING |
| hot_ambient | 模拟环境温度≥60°C，持续 1500 ms | WARNING |
| strong_fire | 火焰分数≥0.8，持续 1000 ms | ALARM |
| smoke_and_heat | 烟雾分数≥0.6 且温度≥60°C，时间对齐，持续 1000 ms | ALARM |
| clear | 烟火分数均<0.15，温度<40°C，时间对齐且新鲜，持续 3000 ms | NORMAL |

默认最大数据年龄 1500 ms、区间连接限制 1000 ms、组合时间偏差 500 ms。视觉 confidence_floor 高于 0.15 时，空检测不能满足 clear；仍可使用实际存在的高分框进行升级。ROI 字段保留供追踪，首版规则按全图判断，不借用示例 ROI 形成物理距离结论。

## 把 P2 结果接进来

```powershell
.\.venv\Scripts\python.exe -m tools.adapt_p2_fusion --run experiments/p2_expanded_pipeline_check/video --timeline experiments/p3_bridge_timeline.json --output experiments/p3_adapter_next
.\.venv\Scripts\python.exe -m tools.verify_p3_bridge --bridge experiments/p3_adapter_next --output experiments/p3_bridge_next
```

适配器强制提供显式模拟时间清单，每个 frame_id 恰好出现一次；不能按帧号暗中补时间。原始 source_timestamp_ms、时间来源、原输入哈希、预测文件哈希和模型身份保留在 provenance 中。原运行须 complete，原配置与配置快照语义须一致，源图/视频哈希需通过。

这里沿用的三帧视频由静态图组成。时间清单中的 100 ms 延迟是人为设置，没有被写成实测推理延迟。此流程验证格式和时间处理，不验证真实火情事件。

## 输出与排错

- `snapshots.jsonl`：每个 tick 的风险、有效性、健康、原因、年龄、当前记录身份及持续区间。
- `events.jsonl`：风险等级、评估有效性或健康状态/健康原因改变时的事件，包含稳定 event_id、前后状态、规则和配置身份。
- `retained_risk_basis`：当前保留等级最初建立时的规则及起止支持记录 ID。完整中间观察在输入、快照和 active_intervals 中追溯。
- `report.json`：完成/失败状态、输入及程序身份、去重、忽略旧记录和未消费未来记录。

错误输入会非零退出并保存 failed 报告；输出目录已存在则直接拒绝覆盖。变化来源必须明确，不能把未来或重复输入偷偷修成可用证据。文件中完整校验未来记录属于输入完整性检查，它们不会提前参与风险规则。

核验入口：`python -m unittest discover -s tests -v`。下一步应增加真实连续公开视频的事件评测协议，之后再接额外传感器与实际时钟映射。
