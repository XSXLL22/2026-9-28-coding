# P2 电脑端视觉基线操作说明

本阶段实现离线图片、视频、帧目录推理，以及训练、96/128 输入对照评估、固定置信度误检漏检统计。现场采集暂缓。主项目保持三类；公开 D-Fire 试验只训练 smoke/fire 两类，leaf_pile 不支持。

后续扩充版已完成，最新权重为 `experiments/p2_expanded_train/fit/weights/best.pt`，见 [扩充数据操作说明](P2扩充数据操作说明.md) 与 [实测报告](../experiments/P2扩充实验报告.md)。下方 80 张数据和旧权重命令保留用于复现最初试验。

## 环境

项目使用 `.venv` 中的 Python 3.12。直接依赖在 `requirements-p2.txt`，验证完成后的完整依赖在 `requirements-p2.lock.txt`。全部命令从项目根目录执行。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-p2.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

当前安装的是 CPU 版 PyTorch，全部已验证命令使用 `--device cpu`。完整锁文件中的 `+cpu` 轮子需要对应的 CPU 包索引；重建时先安装匹配的 CPU 版 torch/torchvision，再安装本项目依赖。普通终端通常已有处理器架构变量；若受限终端出现 Polars `unknown feature flag: 'sse3'` 且变量为空，先从 Windows 系统环境恢复真实值，再运行训练（不要禁用 CPU 检查）：

```powershell
if (-not $env:PROCESSOR_ARCHITECTURE) {
    $env:PROCESSOR_ARCHITECTURE = [System.Environment]::GetEnvironmentVariable('PROCESSOR_ARCHITECTURE', 'Machine')
}
```

基线使用 Ultralytics 8.3.228 和 YOLOv8n。它是软件对照模型，尚未改造成 FPGA 友好结构。原始 COCO 权重不能检测本项目烟火类别；必须经过对应数据微调，或仅在显式允许通用类别的管线试验中使用。

## 公开小样本试验

```powershell
.\.venv\Scripts\python.exe tools\fetch_public_pilot.py
```

脚本从 D-Fire 官方 README 链接的 Kaggle 镜像读取版本 1，固定选择 train 48、val 16、test 16 张图及标签。保留镜像既有划分并记录 SHA256，不把未知原始视频分组伪装为已知。全部放在 `datasets/public_pilot`，不混入校园正式台账。完整数据约 3.1 GB，本命令只下载小样本。

试验训练：

```powershell
.\.venv\Scripts\python.exe tools\prepare_public_pilot.py
.\.venv\Scripts\python.exe -m training.baseline train --data datasets/public_pilot_prepared/data.yaml --weights models/yolov8n.pt --output experiments/my_training --epochs 50 --batch 8 --device cpu
```

下载结果保留原始标签。已发现的两处越界框在独立的 `public_pilot_prepared` 副本内按可见边界裁剪，修改记录、原始与处理后哈希见 `preparation.json`；`audit.json` 是清洗后的严格检查结果。工作区已有副本时不必重复执行准备命令，它会拒绝覆盖。已完成的训练输出为 `experiments/p2_pilot_train_50epochs`；两轮流程试训保存在 `experiments/p2_pilot_train_verified`。

原始权重来自 [Ultralytics 官方发布](https://github.com/ultralytics/assets/releases/download/v8.3.0/yolov8n.pt)。训练入口会先检查图片可解码、标签边界、类覆盖和跨集合完全重复；近重复和原始视频分组仍需人工核验。仅运行两轮只证明训练流程可执行，不能证明模型已收敛或具备报警能力。

每次指定一个尚不存在的输出目录，防止覆盖旧实验。训练和评估异常会写入 `report.json` 的 failed 状态并以非零码退出。训练后的权重实际路径见该文件。

## 推理

```powershell
.\.venv\Scripts\python.exe -m runtime.vision --weights experiments/p2_pilot_train_50epochs/fit/weights/best.pt --source datasets/public_pilot_prepared/images/val --output experiments/my_inference --imgsz 128 --device cpu --save-images
```

`--source` 可以是单张图片、图片目录或视频文件。图片目录按文件名排序；没有真实时间信息时，时间戳为 null。若目录是明确的等间隔帧序列，可传入 `--sequence-fps`，输出会标明这是用户指定帧率推算的时间。视频优先采用容器时间戳，回退到名义帧率时也会注明。

`configs/vision.json` 配置 ROI 和模型类别映射。当前 ROI 为示例凸多边形，须在现场数据可用后标定。网络内部使用等比例填充，Ultralytics 返回框已还原到原图；本入口在原图上计算框与 ROI 相交面积占框面积的比例，没有再次缩放坐标。

## 输出

- `detections.jsonl`：每帧原始尺寸、时间来源、模型哈希、框、置信度、原始类别、项目类别、ROI 占比和耗时。
- `run.json`：参数、依赖、模型与输入哈希、状态、平均/P95 推理耗时和帧处理速度。
- `config_snapshot.json`：本次使用的配置快照。
- `frame_*.jpg`：可选标注图。

静态图的时间未知不填当前时间；未映射的模型类别输出项目类别 null；没有落叶模型时记录不支持类别。帧处理速度包含读取、首次输入哈希、推理、ROI、结果写入和可选 JPEG，不包含权重加载和预热。它不是 FPGA FPS。

## 评估和复现

```powershell
.\.venv\Scripts\python.exe -m training.baseline evaluate --data datasets/public_pilot_prepared/data.yaml --weights experiments/p2_pilot_train_50epochs/fit/weights/best.pt --output experiments/new_evaluation --device cpu
.\.venv\Scripts\python.exe tools\verify_p2_pipeline.py --weights experiments/p2_pilot_train_50epochs/fit/weights/best.pt --images datasets/public_pilot_prepared/images/val --labels datasets/public_pilot_prepared/labels/val --output experiments/new_pipeline_check
```

评估默认只使用 val，同时报告 96 和 128 输入的每类 P/R、AP50、AP50:95 和模型阶段耗时。这里 P/R 是 Ultralytics 按 F1 选择工作点的指标，不能与默认 conf=0.25 的误检漏检直接混用。固定工作点由 `training.error_analysis` 根据实际推理 JSONL 以 IoU=0.5 统计 TP/FP/FN；无分母的比例输出 null。测试集保留，不用于选输入尺寸。

端到端验证会对同一批图片运行两次，检查检测结果是否完全一致，并运行单图、目录和由三张静态图生成的视频夹具。该视频只验证输入和时间戳，不验证真实火情时序。
