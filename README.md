# 校园火险多源感知预警系统

本项目面向校园配电设施周边，检测烟雾、明火和落叶堆积，结合传感器输出正常、关注、预警、报警四级风险。以轻量化检测模型、FPGA 核心算子加速和可复现验证为毕业设计重点。

目前已完成 P2 电脑端视觉基线与 D0 识别诊断，并实现 P3 首版离线模拟融合、P4 定点量化与整数参考、P5.0 最小卷积 RTL 仿真闭环。现实采集按用户要求暂缓；硬件尚未采购，RTL 首版算子已在仿真中逐位验收，但**尚未综合、未上板**。硬件总预算为人民币 1000 元。原始任务书与开题报告为校内材料，未随本仓库发布。各阶段可运行方式和验收边界见下方说明。

## 仓库范围

本仓库**只包含代码与文字记录**，不含模型权重与数据集。

| 类别 | 在仓库内 | 说明 |
|---|---|---|
| 源码 | 是 | `runtime/`(融合与视觉运行时)、`training/`(训练/校准/导出/打包/PTQ 评估)、`tools/`(构建与校验入口)、`hardware/`(Verilog-2001 RTL 与测试台)、`configs/`、`reference/`(Python 与 C 双整数参考实现) |
| 测试 | 是 | `tests/`,含 `tests/golden/` 冻结向量夹具;多数用例开箱即可运行,少数需要本地的模型与数据(见下文"快速开始") |
| 文字记录 | 是 | `docs/`(设计、计划与交接)、`experiments/*.md`(每个节点的实测简报) |
| 数据集 | 否 | 需自行准备;`datasets/README.md` 描述三类标注、数据台账与划分检查入口 |
| 模型权重与量化模型包 | 否 | `*.pt` 与 `training/export/*/model_pack.bin` 均不入库 |
| 实验逐次运行产物 | 否 | 日志、图像、生成的 RTL 向量等留在本地;`experiments/*/` 已被忽略 |

因为模型与数据不在仓库内，部分文档中的链接或复现命令会指向本地才有的文件，这属预期现象；`experiments/*.md` 的结论与判据本身是完整的。P5 的 RTL 仿真向量由 `tools/build_p5_vectors.py` 确定性重新生成(固定种子)，无需外部数据。

## 快速开始

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-p2.txt    # Windows
# .venv/bin/python -m pip install -r requirements-p2.txt          # Linux / macOS

# 回归测试(完整本地环境 121 项;缺本地模型与数据时的表现见下节)
.venv/Scripts/python.exe -m unittest discover -s tests -t . -v
```

### 测试对本地文件的依赖

绝大多数用例只依赖 `tests/golden/` 内随仓库提供的冻结夹具，开箱即可运行。余下用例需要仓库外的本地文件，**只拿到本仓库时会报错，属预期**：

| 本地文件 | 影响 |
|---|---|
| `models/yolov8n.pt` 训练权重 | `test_exporter.GraphAuditTests` 的 `setUpClass` 失败，该类 5 个用例未运行 |
| `training/export/p4_baseline128_v1/model_pack.bin` 量化模型包 | `test_int_reference` 的 `IntReferenceTests`、`PackReaderTests` 的 `setUpClass` 失败，共 6 个用例未运行 |
| `datasets/public_expanded_comparison/labels/val/*.txt` 标签 | `test_ptq_geometry` 中 2 个用例直接报错 |

两种环境下的实测结果：

| 环境 | 结果 |
|---|---|
| 完整本地环境(具备上述三类文件) | **121 项全部通过** |
| 仅本仓库(缺上述文件) | 运行 110 项:104 通过、1 跳过、5 报错;另有 11 个用例因 `setUpClass` 失败未运行 |

补齐上述文件即回到完整的 121 项。这里没有改成"缺文件就跳过"——本项目的验收纪律要求失败可见，不用静默跳过掩盖缺失。

RTL 仿真另需 [Icarus Verilog](http://iverilog.icarus.com/) 11.0 或更新版本(`iverilog -V` 自检),入口见 `tools/run_p5_sim.py`。

2026-09-28 完成 E0 / E1 / P5.0 三个节点(交接见 [E0/E1/P5 完成后交接](docs/E0_E1_P5完成后交接.md),累计 **121 项**测试通过):

- [E0 评估坐标修复](experiments/P4评估修复简报.md):原 −4.02pp 的根因是评估坐标错误(GT 在原始像素空间、检测画布是 letterbox 画布)。修复后 109 张重算 FP32 **31.53%** / INT8 **30.88%**,量化损失 **−0.65pp**, **−3pp 探索门 PASS**;旧报告与失败证据全部保留。
- [E1 合同与资源复核](experiments/P4合同与资源复核简报.md):定点合同 v1.2→**v1.3**。旧累加界 `127·Σ|qw|` 不保守(int8 的 −128 经 `np.abs` 会静默溢出),改为逐输出通道 `B[o] = |qb[o]| + 128·Σ|qw[o,:]|`,权重先展宽 int64,越界在打包时真实抛错。资源估算按 Zynq-7010(80 DSP)/7020(220 DSP)分列。另发现 **MinGW gcc 13.2.0 不可重复构建**,故可执行文件哈希只能作溯源记录,判据改为行为一致。
- [P5.0 最小卷积 RTL 闭环](experiments/P5最小卷积仿真简报.md):无硬件的最小 3×3 卷积 RTL,9 个冻结向量 × **19/19 场景**输出与 Python 整数参考**逐字节相等**,含**真实层 64×64×8×8 的 4096 个输出**;4 个可打开 VCD。过程中修掉两个会改变结论的缺陷(RTL 加载计数器只算不存、测试台两场景漏 `$readmemh` 致全 x 输入却仍打印 PASS)。**未综合、未做时序分析、未上板**,周期数是仿真测量值,不是性能声明。

本轮未启动 QAT、未切换默认模型(仍为原始 FP32 128)、未采购硬件、未使用 16 张冻结测试图;真实数据采集仍暂缓。
