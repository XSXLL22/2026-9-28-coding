# P5 最小卷积仿真简报(P5.0)

2026-09-28。按[下一轮执行计划](../docs/下一轮执行计划_E0_E1_P5_20260928.md) P5.0 节点完成:**无硬件的最小 3×3 卷积 RTL 闭环**。9 个冻结向量、19 个场景全部通过,输出与向量生成时(仿真之前)由 Python 整数参考导出的 pre-SiLU 边界**逐字节相等**;真实层 64×64×8×8 的 4096 个输出同样逐字节相等。周期数与仿真时间已记录,**未做综合、未宣称频率或板上性能**。

## P5.0a 接口与向量格式冻结(实现前)

[hardware/rtl/INTERFACE.md](../hardware/rtl/INTERFACE.md) 先于任何 RTL 编写。冻结内容:同步复位、配置口仅在 IDLE 可写、start/done/error 语义、CHW 输入输出与 OIHW 权重布局、零填充值、偏置只加一次、每通道 M/shift、valid/ready 握手与数据稳定要求、7 项任务语义、3 个错误码语义、首版支持域与拒绝规则。

**修订一次(p5.0a → p5.0b)**:原第 2/3 节把权重流写成 `cout·9 个 int8`,**漏乘 cin**。3×3 卷积每个输出通道需要 cin·9 个权重。修正发生在任何向量生成或 RTL 验收之前(当时只有接口文档与 `mac_array.v`/`requant_sat.v`,卷积核心尚不存在),按合同修订纪律升版本并记录。

向量格式(`p5v-1`):每个向量目录含 `input.mem`/`weight.mem`/`param.mem`/`expected.mem` 与 `vector.json`。`vector.json` 记录版本、层名、包哈希、输入/输出 shape、布局、stride/padding、每文件 sha256、随机种子、累加期望区间、M/shift、以及 pre-SiLU 期望的 sha256。**期望值只在生成阶段由 `conv2d_int8_requant(conv2d_int8_accumulate(x, node))` 产生,RTL 不参与;向量生成后冻结**,`run_p5_sim.py` 启动时校验 manifest 中每个文件的哈希,被改动即拒绝运行。

`conv2d_int8` 内部含 SiLU,不能直接取其输出当 PL 边界期望。为此把 Python 参考拆为三个可审计函数(`conv2d_int8_accumulate` / `conv2d_int8_requant` / `conv2d_int8`),拆分后重跑 15 个 golden 向量仍全部逐位一致,整网输出未改变。

## P5.0c 时序与协议检查

测试台([hardware/tb/tb_conv3x3.v](../hardware/tb/tb_conv3x3.v))独立断言,任一失败 `$fatal` → vvp 非零退出:

- 输出握手取消前 `out_valid` 不得撤、`out_data` 不得变(逐周期检查)。
- 输出含 x 即失败(见「发现并修正的缺陷」)。
- 全剧 4000 万周期看门狗,死锁即失败而非挂起。
- 成功输出数严格等于 Cout×Hout×Wout。
- 加载阶段有 `LOAD_TIMEOUT`(10 万周期无握手),参数流不足由**核心自己**报错。

| 场景 | 覆盖 | 结果 |
|---|---|---|
| basic ×9 | 每个向量常规运行 | 逐字节相等 |
| wave ×2 / stall ×2 | 随机输入停顿 + 随机输出反压(种子 20260928);结果须与无停顿运行完全一致 | 逐字节相等,`stall_real` 2424169 周期 vs 无停顿 2408449 |
| reset_mid ×2 | 任务中同步复位;复位后无输出、无 done、不再 busy;随后重新提交必须完成 | 通过 |
| two_tasks | 连续两任务不同几何;第二个为全零权重/偏置,第一任务的残留会表现为非零输出 | 通过 |
| bad_config | cin=0 被拒(`UNSUPPORTED_CONFIG`),无输出、不 busy;随后同一向量按真实几何正常跑完 | 通过 |
| locked_config | BUSY 期间写配置被拒(`CONFIG_LOCKED`),锁存的 h 不被改写,任务仍产出正确字节 | 通过 |
| param_underflow | 少一个参数字:核心自行报 `PARAM_UNDERFLOW`,无输出,之后仍可复用 | 通过 |

**19/19 场景通过**(`p5_minimal_conv_v1/logs/full_suite.txt`,退出码 0)。周期数为 DUT `cycle_count` 的仿真测量值,真实层 2408449 周期与手算一致(输入装载 4096 + 权重装载 36864 + 4096×578 计算 + 1)。

## 发现并修正的缺陷(全部记录,未掩盖)

1. **RTL:`in_cnt/wt_cnt/p_cnt` 只算不存**。三个计数器有 `*_cnt_n` 下一值,但加载分支里从没写回寄存器,`in_ready` 恒为真而 `in_cnt` 恒为 0,任务永远停在 LOAD_IN。测试台首次运行即卡死(看门狗超时)暴露该问题。修正为在各自握手分支内写回 `*_cnt`。**这是测试台存在的意义,不是返工。**
2. **测试台:场景 5/6 未加载向量文件**。这两个场景手工驱动数据流,却漏掉了 `$readmemh`,于是喂入全 x。测试台自身的断言(输出数量、错误码)全部通过、还打印了 `TB_PASS`,**只有比较器发现输出全是 `xx`**。这正是计划里「不能靠搜索控制台的 PASS 作为唯一验收」所指的情形。已补 `$readmemh`(带显式地址范围),并在测试台中对输出加 `^out_data === 1'bx` 断言。
3. **测试台:场景 2 残留整数组 `$readmemh`**,对小于上限的向量产生 "not enough words" 噪声警告;改为显式范围,顺带把「文件词数必须与几何一致」变成隐式检查。
4. **运行器:Windows 文本模式**使 `$fdisplay` 写出 CRLF,与 LF 的 `expected.mem` 无法做真正的逐字节比较。改为 `"wb"` + `$fwrite`,比较器保持零归一化。
5. **运行器:解码崩溃**。iverilog 会用控制台代码页打印含中文的绝对路径,vvp 输出不是合法 UTF-8;`text=True` 会让读取线程抛异常并把一次真实运行变成运行器崩溃。改为捕获字节并以 `errors='replace'` 解码。

## 限制

- **没有综合、没有时序分析、没有上板、没有功耗数据**;周期数是仿真测量,不是性能声明。真实层 2408449 周期/4096 输出对应单 MAC 结构,**远不是**可用吞吐。
- 首版只支持 3×3、stride=1、pad=1;不支持行缓存、乒乓、通道分块、AXI 配置、整网调度(P5.1+)。片上存储器按 64 通道上限配置,超过即拒绝,不是「支持」。
- 卷积核心不实例化 SiLU 查表;PL 边界止于 pre-SiLU 重量化 int8。SiLU 仍在 PS_INT 一侧,与分工文档一致。
- 真实验证只用了**一个**受支持层(`model.6.m.0.cv1`)与**一张**冻结开发图;其余层、其余图未做 RTL 验证。整网 RTL 尚未存在,不能由本节点推断整网正确。
- 未做形式验证、未做覆盖率统计;向量是「按风险选点」而非穷举,覆盖表已如实列出。
- 与真实环境(现场图像、真实烟雾/落叶、实际部署光照)无关;真实数据采集仍按计划推迟。
