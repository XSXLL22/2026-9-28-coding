## E1.1 数值域与实际拒绝行为(合同 v1.3 §4/§6)

三处已修正:

| 项 | v1.2(有问题) | v1.3(修正后) |
|---|---|---|
| 累加界 | `127·Σ\|qw\|` 乘积式,不保守;`np.abs` 对 int8 的 −128 静默溢出回 −128 | 逐输出通道 `B[o] = \|qb[o]\| + 128·Σ\|qw[o,:]\|`,权重先展宽 int64 再取绝对值(激活域 [−128,127],\|qx\| 可达 128) |
| 越界处理 | 仅调用点注释声称 "raises",函数本身不检查 | `accumulation_bound` 自身抛 `ValueError`;偏置在转 int32/写包之前拒绝 |
| 移位范围 | 未限定 | 显式 `n ∈ [0, 62]`;`n=0` 合法(y = t),`n<0`(scale ≥ 2³⁰)与 `n>62` 在打包时拒绝(C/RTL 负移位是未定义行为) |
| 重量化中间位宽 | 只检查 int32 累加 | 以 Python 精确整数证明 `\|acc·M + half\| ≤ (2³¹−1)² + 2⁶¹ < 2⁶³`,打包时执行该检查 |

测试 `tests/test_numeric_bounds.py`(11 项,期望值全部手算/独立高精度给出,不由被测函数生成):int8 `abs(-128)` 展宽、恰好等于 2³¹−1 的精确边界被接受、再多一项权重即被拒、偏置单独越界被拒、乘子归一化边界(n=0 合法 / 负移位拒绝 / 过小 scale 拒绝 / shift 上限)、合同舍入表(−5→−1、−6→−1、−7→−2)、shift=0 直通、饱和两端。

## E1.2 版本与回归传播(变更类别 2)

**已发包数值未变。** 独立核验:v1 与 v2 模型包逐字节比较,3103332 字节中仅 **15 字节不同**,全部位于元数据字符串——`p4-contract-1.2 → 1.3`(1 字节)与 `worst_accumulation_bound_ratio` 由 0.017328… 改为新公式下的 0.006799…(14 字节)。权重、乘子、SiLU 查表、层描述符正文完全一致。因此 E0 在 v1 包上得到的量化结论对 v2 包同样成立。

C 参考重新编译到本轮独立构建目录(不复用任何旧 exe):

- 命令 `gcc -std=c11 -O2 -Wall -Wextra -o .../build/int_reference.exe reference/c/int_reference.c`;退出码 0;**stderr 为空(零警告)**。日志:`p4_contract_resource_recheck_v1/build/compile_stdout.log`、`compile_stderr.log`。
- 源码哈希 `ca9c93b9…` 与 golden 报告 `c_source_sha256` 一致。
- 15 个向量 × (104 节点 ×13 + 1 节点 ×1)Python↔C 逐位一致,`status=passed`;且 `v2_pack_same_outputs=true`(v1/v2 包输出逐字节相同)。

**方法学发现(重要,影响今后所有验收)**:MinGW gcc 13.2.0 **不可重复构建**——同一源码、同一命令、同一目录下连续两次编译产物哈希不同(文件大小恒为 85919 字节,内容有差异;疑为 PE 头时间戳/构建 ID)。因此可执行文件哈希只能作为「本次运行用了哪个产物」的溯源记录,**不能**用作"重编成功"的判据。真正的判据是行为一致:用重新编译到规范路径 `reference/c/int_reference.exe` 的新二进制(哈希 `9434a7d0…`,与执行者当时所用 `4117b560…` 不同)重跑全部 15 向量,**依旧 15/15 逐位一致**,证明两次构建行为等价。报告:`p4_contract_resource_recheck_v1/golden_canonical_rebuild/report.json`。

同时消除了一个隐患:`tools/verify_golden_vectors.py` 的默认 `--c-binary` 指向 `reference/c/int_reference.exe`,而该路径此前残留的是 E1 之前编译的旧二进制。现已用当前源码重新编译覆盖,规范路径与独立构建目录两份产物均与当前源码对应。

## E1.3 资源与带宽估算(已重写)

新版报告:[p4_contract_resource_recheck_v1/resource/](../experiments/p4_contract_resource_recheck_v1/resource/P4.6资源与带宽报告.md)。旧版「两器件共用 220 DSP」「严格上下界」结论已撤回。

- **器件分离**(依据 AMD Zynq-7000 Product Selection Guide):Zynq-7010 为 80 DSP,仅算力天花板 **61.9 FPS**;Zynq-7020 为 220 DSP,**170.1 FPS**(125 MHz 假设、满占流水,非吞吐声明)。
- **静态量**:161.65 MMAC/帧;权重+偏置+乘子+移位 2993.6 KiB;逐层激活读写 1323.7 KiB/帧;累加界最坏占 int31 的 0.68%。
- **设计量**:首版为单 MAC/小规模展开,未假设行缓存、乒乓、通道分块;权重供给三场景(全驻留 / 逐层加载 / 分块重载)标注为未决定。
- **场景估算**:零复用 DDR 流量上界 4317.2 KiB/帧;SiLU 留在 PS 时每个卷积输出一次 PS↔PL 往返,额外 1323.7 KiB/帧。
- **未知量显式保留**:综合频率、DSP 映射效率、AXI 效率、PS 后处理耗时、DDR 延迟、片上内存可行性——无证据不填数。
