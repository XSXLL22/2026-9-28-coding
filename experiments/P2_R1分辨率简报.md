# P2 R1 配套 320 分辨率实验简报

2026-09-27。50 轮训练、共同开发验证、固定工作点推理及逐图对照已完成。

按 [训练前计划](P2_R1实验计划.md)，唯一配方变化为输入 128 → 320。训练数据、初始化、种子、batch、优化器及增强配置一致；实际参数检查通过。50 轮 Mosaic 均启用。

## 本轮结论

R1 是值得保留的高分辨率软件候选。mAP50 提高 13.62 个百分点，固定工作点正确检出 50 → 71，小目标 3/93 → 23/93。新增净检出的 21 个目标中，20 个来自固定 128 参考尺度下的小目标组；这支持低分辨率是当前限制因素之一，但不能证明它是唯一原因。

代价同样明确：误检框 30 → 48，烟雾 TP 仍为 36、FP 16 → 23。原 128 模型继续作为基线和默认，不把 R1 自动接入 P3 或替换硬件目标。后续优先确认收益可重复，并分析高分辨率新增误检。

## 误检分布与人工复核

负样本上的 FP 框为 10 → 6；含真值目标图片上的 FP 为 20 → 42。因此总 FP 上升并非负样本误检图片增多，不能将 48 个 FP 都解释为无火场景误报警。整体框精确率 62.50% → 59.66%，目标召回率 30.86% → 43.83%；明火召回率 15.56% → 38.89%，烟雾召回率维持 50.00%。

按补检数、丢失数和新增 FP 排序，各选一张并打开新旧复核图（不是全量人工标注审核）：

- `WEB05286.jpg`：原模型没有匹配到该图目标；R1 匹配到 1 个烟雾和 3 个明火框，仍漏掉边缘两处明火和一处烟雾。新烟雾 FP 覆盖了真实烟雾附近更宽的区域，属于匹配失败，不能直接认定为无烟误认。
- `WEB06156.jpg`：R1 找回右侧两处明火，但左侧原本匹配的明火框变大、位置范围改变后失配，右侧另有重叠局部框形成 FP。显示收益与定位/重复框问题可以同时存在。
- `WEB04713.jpg`：两侧青色装饰边缘被 R1 标为烟雾；中心烟雾框过大，明火框只覆盖标注目标的一部分，均未达到匹配要求。此图 TP 仍为 0，FP 从 1 增至 4。后续需分别处理背景误认、范围不一致和重复预测，不能只调低置信度。

没有更改标签或放宽匹配规则。上述观察不等于确认数据标注错误。

## 本机开销

本次训练入口含训练和训练集配套验证约 1210.5 秒。既有 128 推理记录与本次 320 推理的平均单图预测时间为 10.28 → 25.47 ms，P95 为 11.49 → 28.08 ms；包含读取、序列化等环节的帧循环约 65.43 → 32.56 FPS。两次记录不是同期配对基准，只说明本机观察到的开销增加，不能作为 FPGA 吞吐或严格性能倍率。
