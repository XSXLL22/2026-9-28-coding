# P4 评估修复简报(E0)

2026-09-28。按[下一轮执行计划](../docs/下一轮执行计划_E0_E1_P5_20260928.md) E0 节点完成:修复 P4.7 评估脚本的坐标错误,经 F0/F1 一致性门后重算 FP32/INT8。**修正后量化损失 -0.65pp,在 -3pp 探索目标内,QAT 决策门 PASS——旧 -4.02pp 结论撤回。**

## 错误与复现(E0.1)

旧 `training/ptq_eval.py` 的 `load_gt` 把归一化标签直接乘 128(拉伸到 128×128),而预测框在 letterbox 画布空间;109 张开发图全部非正方形,GT 与预测不共坐标空间。代表样本 WEB06156.jpg(768×432 → 128×72 内容,上下补 28):第一个火框正确画布坐标 [29.6, 82.4, 37.1, 90.3],旧 GT 却落在 [29.6, 96.7, 37.1, 110.7](部分在补边区),完美预测 IoU = 0。

失败复现日志:[e0_evidence/e0_1_failing_tests_before_fix.log](p4_eval_recheck_v1/e0_evidence/e0_1_failing_tests_before_fix.log)(12 errors + 1 failure:无 `LetterboxTransform` API、旧签名、拉伸坐标断言失败)。修复后回归:`tests/test_ptq_geometry.py` 11 项,覆盖横向/纵向/正方形、奇偶补边、画布越界裁剪、空标注、完美预测匹配、几何往返(容差 1e-4)。

## 修复设计(E0.2/E0.3)

- **唯一坐标实现**:`LetterboxTransform` 类持有原图尺寸、实现后增益(取整后实际尺寸/原尺寸)、四侧补边;正向(letterbox)与逆变换共用同一实例。**匹配与 AP 统一在原图像素空间**:GT = 归一化标签 × 原图宽高;预测框 NMS(画布空间)后逆映射回原图并裁剪。补边约定与框架一致(等比 + 取整 + 均分补边)。
- **来源强制校验**(`verify_sources`,推理前执行,失败即拒绝):权重哈希 = 包声明 = 校准报告声明;包哈希 = JSON 清单声明;校准报告哈希 = 包声明;合同版本一致;输入形状 3×128×128;六个 scope scale 按输出节点张量 ID 绑定且有限、为正;109 张图与标签逐一对照冻结 data_audit 哈希。
- 解码器验证升级:与框架自身头解码(NMS 前)逐锚点对比,336 锚点框差 2.7e-4 px、分数差 2.0e-7。

## F0/F1 一致性(E0.4)

F0 = 原框架浮点网络(前向钩子取 6 个检测头原始输出);F1 = 折叠 float 执行器。同一输入张量、同一解码器、同一 AP:

- 逐节点最大绝对误差(109 张 × 6 输出):**4.5e-05**(与 P4.1 的 4.2e-05 一致量级)。
- 端到端 mAP50 差:**0.0pp**(两者均为 31.53%),通过 0.1pp 诊断门。
- 与框架原生 val(库内实现,NMS/实现不同,仅方向参照):库 32.07% vs F0 31.53%,差 0.54pp,来源为 NMS 与 AP 实现差异,已在报告注明不可比性。
